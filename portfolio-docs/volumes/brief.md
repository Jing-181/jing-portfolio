## 二、「八分好」的判定标准

### 两卷通用

1. **每一条都立得住**。一条 = 一个具体的东西（一个人、一首歌、一个地方、一件事），
   不是概括，不是统计噪音。看完能说出「哦，就是这个」。
2. **note 用站点文风**（见第三节），一到三句，能独立读懂，不靠上下文。
3. **不重复**。同一件事只出现一次；宁可合并，不要两张卡说同一件事。
4. **没有空话**。删掉「很有意思」「很特别」这类没有信息量的评语。
5. **事实不许编**。拿不准的年份、名字、细节，留空并标 `待核对`，不要凑。
6. **schema 不破**。字段规范见 `README.md` 第 3 节；改完必须跑通 `node scripts/data.js`。

### 喜好志额外要求

7. **分类均衡**。当前分布：食物 3 / 饮品 4 / 音乐 11 / 影剧 9 / 书 2 / 城市 3 / 其他 5。
   - `游戏` 一栏现在是空的；Jing 说过「太多了先不讲了」，允许空着，但**页面上要有一句得体的说明**，不要像坏掉。
   - 音乐 11 条里有 8 条是我按歌单频次推的艺人卡，属于「统计出来的」，不是她亲口说的。
     要么把依据说清楚（note 里写明），要么收敛。
8. **rating 要有可复述的依据**。现在的 rating 混了两种来源：访谈里的语气、歌单里的出现次数。
   两种都行，但在文件头注释里说清楚哪部分算哪种。

### 经历线额外要求

9. **时间轴不留大段空白**。1997 → 2026，中间有明显断档要补（哪些能补见第四节）。
10. **`est: true` 标得准**。推算的年份必须标；本人确认过的不标（锚点见文件头注释）。
11. **每条是「一件事」，不是「一段时间」**。合并太碎的，拆开太笼统的。
12. **note 里有画面**。经历线的价值在细节（塑料的越南盾、外婆家的夏天），不在年份本身。

## 三、站点文风

这个站的底色是**纸 + 墨 + 中国传统色**，宋体标题、等宽字体点缀。文字也要配得上它。

- 短句为主。一个意思一句话，句号多，逗号少堆。
- 具体压过抽象。写「塑料的纸币」而不是「异国纪念品」；写「天天去图书馆，还在外面租房」而不是「备考很刻苦」。
- **保留她的原话质感**。口语、断句、半截话、犹豫，都是好东西，不要抹平成书面语。
  润色是让它更准、更有画面，不是让它更"正确"。
- 不堆形容词，不用「总的来说」「希望对你有帮助」这类收尾。
- 破折号少用。
- 「不是……是……」这个句式少用。
- 标题用具体名词。「大二 · 广西（德天瀑布）」比「一段旅程」好。

- **不要 git 提交**，主持人统一提交。

- **训练档案（第四卷）**：早先定的是「不许碰、不许问」。2026-10-10 本人主动给了个华为运动健康数据，

杠铃深蹲最近 7 次、哑铃卧推最近 9 次（2026-09-05 到 10-10），加一条硬拉的说明。
她说这堆可以完整记进 md。

**做掉的**：训练档案 16 → **33** 条。开了一个「单次记录层」，跟原来的总结层并列。

- 力量 kind 从 1 条变成 18 条（1 条华为的力量总结 + 1 条硬拉 + 7 条深蹲 + 9 条卧推）。
- 格式：`metric` 放「重量×次数 / 重量×次数 / …」，`tags` 放「N 组, 容量 X kg, 最重 Y kg」。
  标题统一写「杠铃深蹲」「哑铃卧推」，靠 date 区分（跟早先的打算一致）。
- 每组容量逐条验算过，和她给的数字全对上（比如 09-27 深蹲 80×5×4+90×2+80×5=2,180）。
- 文件名下分了三个 `##` 小节：杠铃深蹲 / 哑铃卧推 / 硬拉。解析器不看 `##`，只按 `###` 和 date 排，
  所以 md 里能按动作分组、页面上仍然按日期倒在一条线上。这个结构以后加动作可以直接用。
- 筛选栏 `kinds` 把「力量」提到「跑步」前面（现在力量最多），其余顺序不动。

**排序上的一个副作用**：`parseTraining` 用完整日期字符串降序，所以 `2026-10-10` 排在 `2026-10` 前面。
页面打开（全部）第一眼是最近一次深蹲，总计和年份那张卡被挤到下面。接受这个：
档案本来就该最新的在最上面，要看概览点「总计」或「2026 年」就好。

**没写的**：她没给训练时的体感、组间休息、RPE，也没给背。不编。

校验：训练档案 16 → 33 条，线上正常。

### 2026-10-10 第八段：背日入场 + 解析器支持多行 note

Jing 说「我复制某一天背的记录给你吧，你做参考」，给了一份完整的背日清单：
2026-09-21，75 分钟，7 个动作（引体向上、宽握/窄握高位下拉、坐姿绳索划船、
单臂哑铃划船、反向蝴蝶机、绳索下压），每个动作 3–4 组。

**关键变化**：之前一条记录 = 一个动作（深蹲、卧推各自成条）。背日一次七个动作，
再按动作拆就把一天切碎了。所以定下来：**一条记录 = 一次训练**。
单个动作的一天写在 `metric`，动作多的一天把清单写在 `note`。

**为此刻改的东西**：

- `scripts/data.js` 的 `parseTraining` 加了「续行」：不匹配 `key: value`、
  且以空白开头的行，接到上一个字段后面（用 `\n` 拼）。只改了 training 这个解析器，
  喜好志、经历志没动。
- `assets/css/volumes.css` 的 `.tr-note` 加 `white-space: pre-line`，让换行真的断行。
- `data/training.md` 新增 `## 力量 · 背` 一节，里面一条「背日」。文件头写清了这个约定。

校验：训练档案 33 → 34 条；多行 note 只有背日一条，其他没受影响。

**没定的**：深蹲和卧推那 16 条还是按动作单列的（她当时只给了单个动作的导出）。
到时候她要是把腿日、胸日的完整清单也给了，就统一改成一天一张卡。

**她说完之后还能反悔的**：总结这个粒度是她说的，但“总结到什么程度”是我定的。
现在是一年一条，如果太粗，可以回到按月，或者在年份条目里补一行“两个高点”。
