## 二、「八分好」的判定标准

### 两卷通用

1. **每一条都立得住**。一条 = 一个具体的东西（一个人、一首歌、一个地方、一件事），
   不是概括，不是统计噪音。看完能说出「哦，就是这个」。
2. **note 用站点文风**（见第三节），一到三句，能独立读懂，不靠上下文。
3. **不重复**。同一件事只出现一次；宁可合并，不要两张卡说同一件事。
4. **没有空话**。删掉「很有意思」「很特别」这类没有信息量的评语。
5. **事实不许编**。拿不准的年份、名字、细节，留空并标 `待核对`，不要凑。
6. **schema 不破**。字段规范见 `README.md` 第 3 节；改完必须跑通 `node scripts/data.js`。

### 喜好志额外要求

7. **分类均衡**。当前分布：食物 3 / 饮品 4 / 音乐 11 / 影剧 9 / 书 2 / 城市 3 / 其他 5。
   - `游戏` 一栏现在是空的；Jing 说过「太多了先不讲了」，允许空着，但**页面上要有一句得体的说明**，不要像坏掉。
   - 音乐 11 条里有 8 条是我按歌单频次推的艺人卡，属于「统计出来的」，不是她亲口说的。
     要么把依据说清楚（note 里写明），要么收敛。
8. **rating 要有可复述的依据**。现在的 rating 混了两种来源：访谈里的语气、歌单里的出现次数。
   两种都行，但在文件头注释里说清楚哪部分算哪种。

### 经历线额外要求

9. **时间轴不留大段空白**。1997 → 2026，中间有明显断档要补（哪些能补见第四节）。
10. **`est: true` 标得准**。推算的年份必须标；本人确认过的不标（锚点见文件头注释）。
11. **每条是「一件事」，不是「一段时间」**。合并太碎的，拆开太笼统的。
12. **note 里有画面**。经历线的价值在细节（塑料的越南盾、外婆家的夏天），不在年份本身。

## 三、站点文风

这个站的底色是**纸 + 墨 + 中国传统色**，宋体标题、等宽字体点缀。文字也要配得上它。

- 短句为主。一个意思一句话，句号多，逗号少堆。
- 具体压过抽象。写「塑料的纸币」而不是「异国纪念品」；写「天天去图书馆，还在外面租房」而不是「备考很刻苦」。
- **保留她的原话质感**。口语、断句、半截话、犹豫，都是好东西，不要抹平成书面语。
  润色是让它更准、更有画面，不是让它更"正确"。
- 不堆形容词，不用「总的来说」「希望对你有帮助」这类收尾。
- 破折号少用。
- 「不是……是……」这个句式少用。
- 标题用具体名词。「大二 · 广西（德天瀑布）」比「一段旅程」好。

## 五、分工与边界

| 谁 | 管哪个文件 | 做什么 |
| --- | --- | --- |
| 助手 A（喜好志） | **只动** `data/tastes.md` | 用 raw 数据把音乐/影剧/其他补实；统一文风；收敛冗余；给出 rating 依据 |
| 助手 B（经历线） | **只动** `data/timeline.md` | 补断档、润色 note、校准 est 与 kind |
| Hanako（主持） | 其他所有 | 审稿、跑构建、提交推送、和 Jing 对接 |

边界：

- **一个文件一个主人。** 不要动别人的文件，也不要动 `scripts/`、`assets/`、`pages/`、`README.md`。
- 页面和解析器已经支持全部字段，不需要改代码。真觉得需要加字段，回来提，不要自己改。
- **不要 git 提交**，主持人统一提交。
- 不要为了填满而去编内容。空着 + 标 `待核对` 比编一条好。
